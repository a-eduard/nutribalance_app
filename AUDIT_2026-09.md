## 1. Почему не доходили сообщения за рубежом и через VPN

| # | Причина | Что сделано |
|---|---------|-------------|
| 1 | **Пуши о новых сообщениях не работали вообще.** `functions/index.js` вызывал `admin.firestore()` / `admin.messaging()`, а в firebase-admin v14 этот API удалён. Ошибку глушил `try/catch`, поэтому в логах было тихо. Сломана была и очистка данных при удалении аккаунта | Функции переписаны на модульный API firebase-admin |
| 2 | **Список чатов удалял диалоги.** Если профиль собеседника не загружался (плохая связь или VPN), экран «Чаты» удалял документ чата | Удаление убрано. Правила Firestore теперь запрещают удалять чаты |
| 3 | Список чатов и поиск загружали **всю коллекцию `users`**. На медленном канале это упиралось в таймаут, и экран оставался пустым | Появилась лёгкая коллекция `public_profiles`: её заполняет серверный триггер, по ней работают поиск и имена в чатах |
| 4 | Отправка **ждала ответа сервера** (`await add` и транзакции). Через VPN gRPC-стрим Firestore часто подвисает, а транзакции без сети сразу падают | Отправка стала оптимистичной: сообщение сразу появляется в чате. Если за 7 с подтверждения нет, оно уходит через резервный HTTPS-канал (`sendChatMessage`) |
| 5 | Если стрим «завис», новые сообщения не приходили, и приложение никак об этом не сообщало | Зависший стрим определяется автоматически. Тогда сообщения подтягиваются через HTTPS (`fetchChatMessages`) каждые 12 с, а сверху виден баннер «Нет связи» |
| 6 | Счётчики непрочитанного и сами пуши зависели от клиента | Счётчики, пуши и метаданные чата ведёт сервер (`onNewChatMessage`). Статусы: ⏱ отправляется → ✓ доставлено → ✓✓ прочитано |

Запуск приложения тоже раньше мог зависать через VPN: мешали часовой пояс, RuStore и проверка `isAppInReview`. Теперь инициализация «мягкая»: сбой одной службы не блокирует вход, есть сплэш-экран и кнопка «Повторить».

## 2. Другие исправленные ошибки

**Данные**
- `logMeal` перезаписывал уже записанные приёмы пищи, из-за чего они терялись. Теперь данные объединяются (merge).
- Изменение веса продукта в приёме пищи сохранялось в текущий день, а не в тот, где лежит запись (`dateDocId`).
- Список покупок работал на транзакциях, а они без сети не выполняются. Переписан на обычное чтение и запись.
- Экраны больше не ждут сервер при записи: вода, симптомы, настроение, лекарства, цели, анкета и профиль сохраняются мгновенно, в том числе без сети.
- `manualOvulationDay as int` падал, если в базе лежит дробное число. Такие места теперь приводятся через `num`.
- В календаре «Гармонии» была гонка при быстром переключении дней. Из-за раннего `return` в cheat-day было нельзя записывать еду.

**ИИ (Ева)**
- Лимиты бесплатных запросов списывались на клиенте: их можно было обойти, а иногда списывалось дважды. Теперь их списывает сервер и возвращает попытку, если запрос не удался.
- Фото уходили в функцию в base64, что тяжело через VPN. Теперь фото загружается в Storage, а в функцию передаётся путь к нему.
- Ответ Евы сохраняет сервер, так что он не пропадает, если закрыть экран во время генерации. При перегрузке модели (503) запрос повторяется, системный промпт вынесен в `systemInstruction`.

**Подписки и промокоды**
- Покупки RuStore: учитывается каждый токен, продление засчитывается один раз за период, продукты проверяются по списку разрешённых.
- Промокоды проверяет сервер (`redeemPromo`), START3 можно активировать только один раз.
- Добавлены «Восстановить покупки» и автопроверка подписки, у которой скоро заканчивается срок.

**Прочее**
- Нажатие на пуш открывает нужный чат. Токен уведомлений получается с повтором, а при выходе из аккаунта удаляется.
- Убрано использование `context` после `await`: оно давало падения при показе уведомлений.
- Исправлены выход из Google-аккаунта и удаление аккаунта.
- Добавлен deep link `nutribalance://` для возврата из RuStore.
- В PDF-отчёте кириллица работает на шрифтах из assets, без загрузки из сети.
- Картинки сжаты: `apple_icon` и `empty_diary` уменьшены примерно в 10 раз.

## 5. Как выкатить (порядок важен)

1. **Cloud Functions**
   ```
   cd functions
   npm install
   firebase deploy --only functions
   ```
   Файл `.env` с ключами не менялся. Старые версии приложения продолжат работать: сервер совместим с ними.
2. **Приложение 1.1.0+14.** `flutter pub get` уже выполнен. Собрать `flutter build appbundle --release` (или apk) и опубликовать в RuStore.
3. **Один раз:** войти под аккаунтом поддержки → Профиль → «Обновить публичные профили». Это заполнит `public_profiles` для поиска.
4. **Правила безопасности (этап 1):** `firebase deploy --only firestore:rules,storage`.
   Через 2–4 недели, когда большинство пользователей обновится, поменять в `firebase.json` путь на `security/firestore.rules.strict` и выкатить ещё раз.

> ⚠️ `firebase deploy` без `--only` выкатит сразу и функции, и правила. Правила выкатывайте только после шага 1.

## 6. Что осталось и рекомендации

- **Подпись.** Release-сборка подписывается debug-ключом (`android/app/build.gradle.kts`). Проверьте, каким ключом подписана версия в RuStore. Сменить ключ у опубликованного приложения можно только через процедуру смены подписи в консоли RuStore.
- **Проверка чеков RuStore на сервере** (API RuStore) из Google Cloud без российского прокси недоступна. Сейчас сервер защищает от повторного использования токенов, но доверяет данным покупки с клиента. Полную защиту даст маленькая функция в Yandex Cloud.
- **Правила этапа 1** ещё позволяют пользователю менять свой `isPro/proUntil`: без этого не работают старые версии приложения. Этап 2 (strict) это закрывает.
- **Полная блокировка Google.** Если у части пользователей заблокированы и Firestore, и HTTPS-функции (`*.googleapis.com`, `cloudfunctions.net`), следующий шаг — свой прокси-домен (Cloudflare Worker или Yandex API Gateway) для callable-функций.
- **Мёртвый код**, который можно удалить: `nutrition_stats_screen.dart`, `dashboard/ai_assistants_card.dart`, `dashboard/daily_meals_bottom_sheet.dart`, `widgets/shopping_list_widget.dart`, `ui_widgets.dart`.
- **Промокоды в старых версиях.** После правил этапа 1 они не смогут проверять промокоды напрямую: коллекция `promocodes` закрыта. В новой версии промокоды проверяет сервер.
- **Служебный файл.** В `.git/` остался `stale-index-lock-from-audit.tmp` (переименованный lock-файл), его можно удалить.
